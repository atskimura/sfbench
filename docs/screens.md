# sfbench 画面仕様

sfbench の画面の構成と振る舞いを書く。
検討に使った UI モックは claude.ai 上（[UI モック](https://claude.ai/artifact/CXWNf4x6jaGBJtxMxTqYBo)、閲覧には権限が必要）にあり、この文書はその内容を文章にしたものである。
モックとこの文書が食い違う場合は、この文書に従う。

## 共通のヘッダー

左から順に次のものを置く。

- ロゴと「sfbench」
- 画面の切り替え: SOQL、REST API、Apex のタブ。切り替えても、それぞれの画面の入力、結果、送信中の要求と実行中の Apex は残る
- API 使用量（例: `API 342 / 15,000`）。組織を選ぶまでは出さない
- 組織の切り替えボタン。状態の印、エイリアス、組織の詳しい種別（Developer Edition、Enterprise Edition、Sandbox など。選んだときに組織へ問い合わせた `OrganizationType` と `IsSandbox` から決める）を表示する
- 組織を開くボタン（外部リンクのアイコン）。組織の切り替えボタンの隣に置き、押すと `sf org open` でログイン済みの状態で組織のホームを開く。一度開けばブラウザが Salesforce にログインした状態になり、結果のレコードのリンクがそのまま開ける
- 説明サイトへのリンク（「?」アイコン）。0.1.0 では GitHub の README を開く
- 設定を開くボタン（歯車アイコン）

## 組織の切り替え

組織の切り替えボタンを押すと、組織の一覧がポップオーバーで開く。
組織を切り替えると、作業画面（エディタの内容、Tooling API と Query All の指定、結果、AI の要望と提案）を初期化する。残すのはパネルの開閉だけである。
クエリの実行中や AI の生成中に切り替えると、実行や生成は止まる。

- 上部に、エイリアスかユーザー名で絞り込む入力欄を置く。
- 各行に、状態の印、エイリアス、種別、ユーザー名を表示する。今選んでいる組織は背景色で示す。
- 種別は `sf org list` でわかる範囲で表示する。`orgEdition` があればその値（Developer Edition、Enterprise Edition など）を、なければ Production、Sandbox、Scratch、Dev Hub のいずれかを表示する。
- 本番の組織（Sandbox、Scratch、Developer Edition のいずれでもない組織）は、誤操作しにくいよう赤系の色にする。Developer Edition は本番として扱わない。`orgEdition` がわからない組織は、本番として扱う。
- Scratch には有効期限を表示する。
- 状態の印は、未確認、正常、認証エラーの3つである。一覧はまず接続を確かめずに表示し（`--skip-connection-status`）、サーバーが裏で接続を確かめ終えたら、その結果で印を変える。組織を使ったときの結果でも印を変える。
- 使えない組織は一覧に出さない。削除された組織、トライアルの期限が切れた組織（sf CLI が HTTP 420 を返す）、期限切れか Active でないスクラッチ組織が当たる。
- 再ログインが必要な組織（リフレッシュトークンの失効）は、一覧の下に「再ログインが必要な組織（N件）」として畳んで出す。開くと、再ログインのコマンド（`sf org login web --instance-url <URL> -a <alias>`）をコピーボタン付きで表示する。
- 選んでいる組織は、状態にかかわらず一覧に出す。
- 一覧の下部に「接続を確かめ直す」ボタンを置く。確かめている間は「各組織への接続を確かめています」と表示する。
- 下部に、組織を追加するコマンド（`sf org login web -a <alias>`）をコピーボタン付きで表示する。

組織を選ぶと、オブジェクトの一覧、最近のクエリ、API 使用量がその組織のものに切り替わる。

### 本番の組織を選んでいるとき

組織を選んだときに問い合わせた詳しい種別（`OrganizationType` と `IsSandbox`）から、本番の組織かどうかを決め直す。
Sandbox でも Developer Edition でもない組織が本番である。

- ヘッダーの下に、赤い帯で「本番」（英語の画面では「PRODUCTION」）と組織のエイリアスを常に表示する。選んでいる組織が一覧から消えて種別が分からなくなったときも、本番として扱い、帯にユーザー名を出す。
- データを変えうる操作（REST API の GET 以外の送信と、GET でもデータを変えうるパス（`/services/apexrest/`、`executeAnonymous`）への送信、Apex の実行）では、実行の前に「本番の組織 `<エイリアス>` で `<メソッド> <パス>` を実行します」という確認のダイアログを出す。
- SOQL は読み取りだけなので、確認は出さない。

### 起動時に指定された組織

CLI の入口は組織の名前（エイリアスかユーザー名）をそのまま渡し、画面が組織の一覧と照らして解決する。
一覧の取得には数秒かかることがあるので、その間は「組織の一覧を読み込んでいます」と表示する。
一覧にない名前なら、「sf CLI に `<名前>` という組織はありません」と表示し、組織の一覧を開いた状態にする。
このとき `--run` の指定があっても実行しない。

### 既定の組織がないとき

`-o` を付けずに起動し、sf CLI に既定の組織もない場合は、組織の一覧を開いた状態で始める。

- 組織の切り替えボタンには「Select an org」と表示し、印を灰色にする。
- 一覧の上部に、既定の組織が設定されていないことと、`npx sfbench -o <alias>` または `sf config set target-org <alias>` で指定できることを案内する。
- 作業画面（エディタ、AI の入力欄、結果）は、組織を選ぶまで表示しない。代わりに、組織を選ぶよう案内する。起動時に `--query` が渡されていれば、組織を選んだあとの作業画面のエディタに入れる。

## SOQL の画面

左にオブジェクトと項目の一覧、右上に AI の入力欄とエディタと最近のクエリ、右下に結果を置く。

### オブジェクトと項目の一覧（左）

- 最初はオブジェクトの一覧を表示する。ヘッダーにオブジェクトの数と再読み込みボタンを置く。
- オブジェクトを選ぶと、項目の一覧に切り替わる。ヘッダーに、戻るボタン、オブジェクトの API 名、ラベル、項目の数、読み込んだ時刻、再読み込みボタン、一覧を閉じるボタンを置く。
- 項目の一覧には「Fields」と「Child Relationships」のタブ、絞り込みの入力欄を置く。
- 各項目の行には、チェックボックス、ラベル、API 名、型を表示する。選んだ項目は背景色で示す。
- 参照項目には展開ボタンを置き、展開すると親オブジェクトの項目を一段下げて表示する。

### AI の入力欄、エディタ、最近のクエリ（右上）

- エディタの上に、AI の入力欄と Generate ボタンを置く。その下に、AI に送る情報を札で並べる。オブジェクトの一覧と選ばれたオブジェクトの項目は、いつも送るので押せない札にする。エディタの内容は押して切り替える札にし、押されているときに送る。オブジェクトは AI が選び、開いているオブジェクトは手がかりにする（ai.md「Generate の流れ」）。右端に使う AI を表示する。
- AI が未設定のときは、入力欄の代わりに「AI is off」と設定への案内ボタンを出す。設定で Off を選んだときは何も出さない。
- エディタのツールバーには、Run（⌘↵ / Ctrl+Enter）、Query All、Tooling API、API バージョンの選択（既定は最新。web.md「API バージョン」）、Format、Copy を置く。実行中は Run を押せなくする。Query All と Tooling API はチェックボックスで、同時にはオンにできない。
- 最近のクエリは、エディタの右に置く。各行に、AI に頼んだ文（ある場合）、クエリ、実行時刻、Tooling API の印、最新でない API バージョンの印を表示する。押すとエディタに読み込む。ヘッダーに、最近のクエリを閉じるボタンを置く。

### 結果（右下）

- ヘッダーに、件数、オブジェクト名、所要時間、実行時刻、行の絞り込み、Export CSV を置く。
- 実行中は、結果の位置に「実行しています」と「Cancel」ボタンを出す。押すと実行を止めて結果を空に戻す（Salesforce の側で始まった処理までは止まらない、と注記する）。実行ボタンの位置に置かないのは、連打で誤って取り消さないためである。
- 表は列の見出しを固定し、数値は右寄せで桁をそろえる。
- 18桁のレコード ID は `instanceUrl/<ID>` への通常のリンクにし、新しいタブで開く。
- 行の絞り込みは、読み込み済みの行に対する部分一致である。絞り込み中は続きのページを自動で読み込まず、「残り N 件を読み込む」ボタンを出す。
- Export CSV は、残りが1万件を超えるときに、件数と API の呼び出し回数の見込みをダイアログで出して確認を取る。取得中は、作業を止めずに見えるよう、進み具合と中止のボタンをヘッダーに出す。
- 実行エラーは、結果の位置にエラー文を表示する。Salesforce がクエリを断ったときだけ「Fix with AI」ボタンも出す（AI が Off のときは出さない）。タイムアウトや通信の切断には出さない。

### 結果の表での編集と削除

技術設計は [edit.md](edit.md) にある。

- 結果の見出しの CSV の右に「編集」を置く。Tooling API、集計、Id のない結果では押せない。
- 編集中は、見出しの下に「N件の変更を保存」「変更を取り消す」「N件を削除」「1件でも失敗したら全部取り消す」を出し、表の左端に行の選択列を出す。
- 編集できる列のセルは、ダブルクリックか Enter で入力欄になる（チェックボックスの項目も同じで、開くだけでは値を変えない）。Enter かほかの場所を押すと確定し、Esc で取り消す。変えたセルは色を変える。
- 保存は本番の組織でだけ確認し、削除はいつも件数を示して確認する。失敗した行には印を出し、印にエラー文を出す。
- 保存していない変更があるときに、クエリの実行、組織の切り替え、「編集」のオフ、タブを閉じる操作をすると、捨ててよいか確認する。

### AI の提案カード

AI の出力は、AI の入力欄とエディタの間に提案カードとして表示する。

- エディタに中身があるときは、変更前後の差分を表示する。
- 解釈を1、2文で説明する。
- ボタンは Discard、Replace、Replace & Run（SOQL のみ）である。日本語の画面では「破棄」「置き換え」「置き換えて実行」と表示する（Generate は「生成」、Fix with AI は「AI で直す」）。押すまでエディタは書き換えない。
- 生成中は、進み具合（オブジェクトの選択、項目の読み込み、生成）と Cancel ボタンを表示する。

### パネルの開閉

開閉できるのは次の3つである。
開閉の状態は localStorage に保存する。

- **左の一覧**：閉じると幅 36px の縦の帯になり、オブジェクト名を縦書きで表示する。帯を押すと開く。
- **右上の領域全体**：AI の入力欄、エディタ、最近のクエリをまとめて開閉する。開閉ボタンは、右上の領域と結果の境目の中央に「Hide editor」「Show editor」として置く。閉じると、Run ボタンとクエリの1行目だけの1行になる。
- **最近のクエリ**：閉じると右端の細いボタンになり、エディタが横に広がる。

## REST API の画面

技術設計は [rest.md](rest.md) にある。

- 配置は SOQL の画面にそろえる。上に要求の欄、その右に実行履歴（SOQL の最近のクエリと同じ位置）、下にレスポンスを横幅いっぱいに置く。
- 実行履歴の各行に、メソッド（色分け）、パス、送った時刻、ステータス（応答待ち、不明を含む）を表示する。押すと、要求の欄に読み込む（送らない）。
- 実行履歴は、たたむと細い帯になる。要求の欄は、境目のボタンでたたみ、たたんでいる間はメソッド、パス、送信ボタンの1行を出す。開閉は、SOQL の画面とは別にブラウザに覚える。上の段の高さと実行履歴の幅は、SOQL の画面と同じにする。
- 要求の欄に、メソッドの選択、パス、送信ボタン、ボディとヘッダーのタブを置く。ボディは JSON を色分けし、「整形」で字下げする。ボディを取らないメソッド（GET、DELETE）では、ボディの欄を押せなくする。
- レスポンスには、ステータス、所要時間、大きさ、ヘッダー、本文（JSON なら整形して色分け）を表示する。Salesforce が返した 4xx と 5xx も、エラーではなくレスポンスとして出す。
- データを変えない要求の送信中は、レスポンスの欄にキャンセルを出す（Salesforce の側の処理は止まらない、と注記する）。データを変えうる要求の送信中は、キャンセルを出さず、応答まで待つことをレスポンスの欄に出す（要求の欄をたたんでいても見える）。
- ⌘↵ では送らない（データを変えない要求でも）。送信ボタンで送ることを短く案内する。
- 要求の欄の上に AI の入力欄を置く（[ai-agent.md](ai-agent.md)）。提案カードは、メソッドとパス、ボディの差分、説明を出し、「破棄」と「置き換え」だけを置く。置き換えてもすぐには送らない。提案カードが出ている間は、上の段を高くしてボディの欄が見えるようにする。
- レスポンスが 4xx か 5xx のとき、見出しに「AI で直す」を出す。送った要求とレスポンスの本文を AI に渡す。
- タイムアウトなどで結果が分からなかったときは、その旨を出す。同じ要求を送り直そうとすると、確認のダイアログを出す（本番でなくても）。
- CLI の `--rest` で入力欄を埋めて開いたときは、上部に「コマンドラインから入力しました。データを変更しうるので、送信していません。確かめてから送信を押してください」という案内を出す。`--rest` が別の組織用だったときは、入れずにその旨を出す。

## Apex の画面

技術設計は [apex.md](apex.md) にある。

- 配置は REST API の画面にそろえる。上にコードの欄、その右に実行履歴、下に実行結果を横幅いっぱいに置く。
- コードの欄は Apex を色分けし、行番号を出す。欄の見出しの右に、API バージョンの選択（既定は最新）と実行ボタンを置く。⌘↵ では実行せず、「Apex は実行ボタンで実行します」と短く出す。コードは同じ組織のまま再読み込みしたときだけ戻る。
- 実行履歴の各行に、コードの最初の空でない行、実行した時刻、結果（成功、コンパイルエラー、例外の型、応答待ち、不明）を表示する。押すと、コードの欄に読み込む（実行しない。取り消せる1回の変更）。
- 実行履歴は、たたむと細い帯になる。コードの欄は、境目のボタンでたたみ、たたんでいる間は実行ボタンとコードの最初の行の1行を出す。開閉は、ほかの画面とは別にブラウザに覚える。
- 実行中は、実行結果の欄に「実行しています。取り消せません（最長 N 秒）」と出す。キャンセルは置かない。
- 実行結果の見出しに、結果、所要時間、実行した時刻を出す。実行したあとでコードを変えると、「実行したあとでコードが変わっています」と添える。
- コンパイルエラーと例外では、メッセージと「2行目 5列」のボタンを出し、押すとコードのその位置へ移る。例外では、スタックトレースを開けるようにし、外部への影響（コールアウトなど）は戻らないと注記する。
- デバッグログは、既定で全文を出す。上に検索の欄、「USER_DEBUG だけ」の切り替え、コピー、ダウンロードを置く。検索は一致した箇所をすべて色付けし、Enter、↓、↑ で一致の間を移り、「3/12」のように何件目かを出す。「USER_DEBUG だけ」は、ブラウザに覚える。
- 本番の組織では、実行の前に確認する。同じコードの前の実行の結果が分からないとき、別の実行がまだ応答を待っているとき、実行履歴を読み込めていないときも確認する（本番でなくても）。
- コードの欄の上に AI の入力欄を置く（[ai-agent.md](ai-agent.md)）。提案カードは、いまのコードとの差分と説明を出し、「破棄」と「置き換え」だけを置く。置き換えても実行しない。
- コンパイルエラーと例外では、「AI で直す」を出す。実行したコードとエラー文、行と列を AI に渡す。
- CLI の `--apex` で開いたときは、コードの欄を埋め、上部に「コマンドラインから入力しました。データを変更しうるので、実行していません」という案内を出す。`--apex` が別の組織用だったときは、入れずにその旨を出す。

## 設定

ヘッダーの歯車から、ダイアログで開く。

- **SOQL**：「名前空間を省く」のチェックボックス（既定はオン）。
- **接続**：Salesforce の応答を待つ時間（秒、既定は120）。
- **AI**：Off、Anthropic、OpenAI から選ぶ（既定は Off）。
  - Anthropic か OpenAI を選んだときは、モデルと API キーを入力する。
  - 保存済みの API キーは、欄を空のまま「保存済み」と表示する。入力すれば置き換え、「キーを消す」で消す。キーはこの PC の `~/.sfbench/settings.json` に本人だけが読める形で保存する、と注記する。
  - AI を呼ぶのはボタンを押したときだけで、そのたびに API の料金がかかる、と説明する。
  - AI に送る情報を、AI の欄の中に明示する（オブジェクトと項目の名前、型、選択リストの値、エディタの内容、エラー文。クエリの結果とレコードは送らない）。
  - AI の欄の中に「Test connection」ボタンを置く。選んだ API に短いリクエストを1回送ると注記する。
- ダイアログの下部に Cancel と Save のボタンを置き、その下に sfbench のバージョン、説明サイトへのリンク、GitHub へのリンクを置く。

## 接続できないときの案内

- 期限切れか使用済みの起動用 URL（`/launch/<code>`）を開いたときは、作業画面の代わりに「この URL は使えません。`npx sfbench` を実行して開き直してください」と表示する。
- セッショントークンが無効になったとき（サーバーが止まった、再起動したなど）は、作業画面を残したまま、上部の帯で「sfbench に接続できません。`npx sfbench` を実行して開き直してください」と案内する。エディタの内容は sessionStorage にも保存しておき、失われないようにする。
