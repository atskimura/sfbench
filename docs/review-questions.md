# 設計のレビューで必ず問うこと

設計のレビューをサブエージェントに頼むときは、次の問いを依頼文にそのまま入れる（CLAUDE.md「設計の文書」）。
設計した本人が問いを選ぶと、本人の前提がレビューでも崩れないからである。

1. この問題を、根本的に別のやり方で解けないか。
2. 既存のライブラリ（React や TanStack の部品、ブラウザや Node の標準の API を含む）で済まないか。済むなら、自前で作る理由は十分か。
3. 機能や対象を減らして、問題そのものを小さくできないか。
4. この設計に反対する立場で、採るべきでない理由を論じよ。
5. 「検討した案」の比べ方は公平か。採らなかった案を不当に弱く見積もっていないか。
6. 状態と遷移、失敗したとき、判定の置き場所は具体的に書かれているか。書かれていない場面はどれか。
7. 保守する人がいない前提で、この設計は5年後も読めて直せるか。
