# sfbench 画面の技術設計

区切り2（SOQL の画面）で作る画面側の設計を書く。
画面の見た目と振る舞いは [screens.md](screens.md)、サーバーの API は [design.md](design.md) にあり、この文書はそれらをどう実装するかを決める。

## 範囲

区切り2で作るのは、SOQL の画面、組織の切り替え、組織を開くボタン、設定画面（SOQL と接続の欄）、接続できないときの案内である。
REST API と Apex の画面、AI の入力欄と提案カード、設定画面の AI の欄、結果の表での編集と削除は、区切り2のあとで作る。
区切り2では、ヘッダーの REST API と Apex のタブを出さず、AI に関する表示も（未設定の案内を含めて）出さない。
作っていない機能への入口を見せないためである。

## ライブラリ

画面のライブラリはすべて `devDependencies` に入れ、ビルド時に取り込む。
利用者の実行時の依存にはならない。

| 用途 | ライブラリ | 理由 |
| --- | --- | --- |
| 画面 | React 19 | 決定済み |
| SOQL の解析と組み立て、整形 | `soql-parser-js` 5 | lwc-soql-builder でも使っていた。最後のリリースは 2024年1月の 5.0.2 だが、ビルド時に取り込むので利用者の環境で壊れることはない。`WITH USER_MODE`、`TYPEOF`、`FIELDS(ALL)`、日付リテラル、`GROUP BY ROLLUP` は解析と組み立ての往復で崩れない。Apex のバインド変数（`:foo`）は解析できない |
| エディタ | CodeMirror 6（`@codemirror/view`、`state`、`commands`、`autocomplete`、`language`、`lang-sql`） | 補完の仕組みを持つ。React 用のラッパーは使わず、`useEffect` で直接組み込む。色分けは `lang-sql` の `SQLDialect.define` で SOQL のキーワードを定義する |
| 結果の表の仮想スクロール | `@tanstack/react-virtual` | 数万行の結果でも描画を軽く保つ。表そのものは自分で描く（TanStack Table は列が動的に決まる表には大きすぎる） |
| テスト | Vitest、jsdom、Testing Library | 画面のテストを Node 上で動かす |

`soql-parser-js` が解析できない SOQL（新しい構文、バインド変数など）でも、エディタと実行は使える。
解析できない間は、項目の一覧との同期、整形、補完の文脈の判定のうち解析に頼る部分だけが止まる。

取り込んだライブラリのライセンス表示は、ビルド時に `dist/web/licenses.txt` にまとめて出力し、npm の公開物に含める（区切り2の最後の PR で用意する）。

## ディレクトリ

```
src/web/
  main.tsx, App.tsx      起動と全体の配置
  api/                   サーバーの API を呼ぶ関数（fetch、セッショントークン、エラーの型）
  state/                 アプリの状態（React の Context と useReducer）
  soql/                  SOQL の解析、組み立て、字句の区切り、補完の候補（React に依存しない純粋な関数）
  results/               結果の表の列の決め方、セルの値、CSV（純粋な関数）
  orgs/                  本番の判定などの組織に関する純粋な関数
  components/            画面の部品。部品ごとに *.tsx と *.module.css
  i18n/                  英語と日本語の文言
  styles/tokens.css      デザイントークン
```

`soql/`、`results/`、`orgs/` は React に依存しない純粋な関数にし、単体テストの中心にする。
旧版で不具合が出やすかったのはこの部分（SOQL と項目の選択の同期、結果の列の展開）だからである。

## 状態の持ち方

状態管理のライブラリは使わず、React の Context と `useReducer` で持つ。
状態の数が少なく、外部の依存を増やす理由がないからである。
変わる頻度が違う状態は Context を分け、エディタの入力で結果の表が再描画されないようにする。

| 状態 | 持つ場所 |
| --- | --- |
| セッショントークン | sessionStorage（`api/` が管理） |
| 起動時の指定（組織、クエリ、実行するか） | 起動時に一度だけ使い、保存しない。再読み込みで `--run` を再実行しないためである |
| 組織の一覧、各組織の状態の印（未確認、正常、認証エラー） | `OrgContext` |
| 選んでいる組織、その詳しい種別と名前空間、API 使用量 | `OrgContext`。選んでいる組織のユーザー名は sessionStorage にも保存し、再読み込みで戻す |
| オブジェクトの一覧、describe の結果 | 組織ごとのメモリ上のキャッシュ（サーバーにもキャッシュがあるので、タブの再読み込みで消えてよい） |
| エディタの本文 | CodeMirror が持ち、React の状態にしない。変更のたびに sessionStorage に保存する |
| エディタの解析結果（FROM のオブジェクト、選んでいる項目）、Tooling API と Query All の指定 | `SoqlContext` |
| 結果（生のレコード、列、続きのページの URL、子レコードの表） | `ResultContext` |
| 最近のクエリ | サーバーから取得し、クエリの実行後に取り直す |
| 設定 | サーバーから取得し、設定画面で保存する |
| パネルの開閉 | localStorage |

API 使用量は、組織の API の応答に含まれる `apiUsage` で毎回更新する。

組織を選んだら（起動時、切り替え時、再読み込み時のいずれも）、summary、オブジェクトの一覧、最近のクエリを並行して取得する。
summary は、詳しい種別、本番の帯、名前空間、API 使用量の最初の値の取得元である。
summary が届くまで、本番の判定は組織の一覧の情報（`kind` と `edition`）で行い、名前空間はないものとして扱う。
summary の取得に失敗した場合（Organization を読めないユーザーなど）も同じ扱いを続け、通知は出さない。

組織を切り替えたら、エディタの SOQL と、Tooling API と Query All の指定は残す。
同じ SOQL を別の組織で実行し直す使い方が多いからである。
選んでいるオブジェクトは、新しい組織のオブジェクトの一覧から FROM のオブジェクトを探して導き直し、なければオブジェクトの一覧を表示する。
結果は消し、最近のクエリは新しい組織のものを取得する。

## 起動から作業画面まで

起動用のコードの交換は、React の描画の前に `main.tsx` で1回だけ行う。
`useEffect` で行うと、React の開発時の二重実行で2回送られ、2回目が「使用済み」になるからである。

1. URL が `/launch/<code>` なら、`POST /api/session` でセッショントークンと起動時の指定を受け取る。トークンだけを sessionStorage に保存し、URL を `/` に置き換える。
2. URL が `/` で sessionStorage にトークンがあれば、それを使う（タブの再読み込み）。
3. トークンがなければ、「`npx sfbench` を実行して開いてください」と表示する。
4. 組織の一覧を取得する（数秒かかることがあるので、読み込み中の表示を出す）。
5. 選ぶ組織を決める。起動時の指定があればそれを、なければ sessionStorage に保存した組織を、組織の一覧と照らして選ぶ。起動時の指定が一覧になければ案内を出し、組織の一覧を開く。どちらもなければ、組織の一覧を開いた状態で始める。
6. 起動時の指定にクエリがあればエディタに入れ、`run` があり組織が見つかっていれば実行する。

## エラーの扱い

`api/` は、サーバーの応答を `error.code` で分類し、画面に伝える。
HTTP ステータスを見るのは、`UNAUTHORIZED` の 401（セッションが無効）と 410（起動用の URL が使えない）を分けるときだけである。
サーバーは Salesforce が返した 4xx のステータスをそのまま返すので、ステータスだけで判定すると、Salesforce の 401 を sfbench のセッション切れと取り違えるからである。

| 応答 | 画面の扱い |
| --- | --- |
| 401 `UNAUTHORIZED`（セッションが無効） | 作業画面を残したまま、上部の帯で「sfbench に接続できません。`npx sfbench` を実行して開き直してください」と案内する。エディタの内容は sessionStorage に残っている |
| 410 `UNAUTHORIZED`（起動用の URL が期限切れか使用済み） | 作業画面の代わりに「この URL は使えません」と表示する |
| `ORG_AUTH_ERROR` | その組織の状態の印を認証エラーにする。再ログインのコマンド（`reloginCommand`）をコピーボタン付きで、クエリの実行中なら結果の位置に、それ以外なら通知に出す。組織の一覧にも同じコマンドを出す |
| 503 `SF_CLI_NOT_FOUND` | 作業画面の代わりに、sf CLI のインストールを案内する |
| `SALESFORCE_ERROR` | 実行のエラーなら結果の位置に、それ以外（describe、続きのページ）なら通知に出す。`details`（Salesforce が返した JSON）を開いて見られるようにする |
| `fetch` 自体の失敗（サーバーが止まっている） | 401 と同じ帯で案内する |
| `NOT_FOUND`（組織がない） | 組織の一覧を取り直し、組織の一覧を開いて選び直してもらう |
| そのほか（`SF_CLI_ERROR`、`BAD_REQUEST`、`INTERNAL_ERROR`、`details` のない `SALESFORCE_ERROR`） | 通知に `message` を出す |

組織が1つもない場合は、組織の一覧に「sf CLI でログインした組織がありません」と出し、`sf org login web -a <alias>` を案内する。

読み込み中は、操作した場所（オブジェクトの一覧、項目の一覧、結果、組織の一覧）ごとに読み込み中の表示を出す。

### 遅れて届いた応答

組織の切り替え、クエリの再実行、続きのページの取得中の再実行などで、古い要求の応答が後から届くことがある。
要求ごとに `AbortController` を使い、新しい要求を始めるときに古い要求を中止する。
中止できない場合に備えて、応答を反映する前に、その要求がまだ最新かを世代番号で確かめる。

## SOQL と項目の選択の同期

旧版と同じく、エディタの SOQL を正とし、項目の一覧の選択状態は SOQL から導く。

- **項目を押したとき**: 今の SOQL を `soql-parser-js` で解析し、SELECT 句に項目を足すか外して組み立て直し、整形してエディタに入れる。解析できなければエディタを書き換えず、「SOQL を解析できないので、項目の一覧から変更できません」と案内する。旧版は直前に解析できた内容でエディタを上書きしていたので、書きかけの内容が消えていた。
- **エディタを書き換えたとき**: 入力が止まってから 300 ミリ秒後に解析する。解析できたら、FROM のオブジェクトと SELECT 句の項目から選択状態を作る。FROM のオブジェクトがオブジェクトの一覧にあれば、左の一覧をそのオブジェクトに切り替える。一覧になければ（存在しない名前など）切り替えない。解析できなければ、選択状態は直前のまま変えない。エディタを空にしたら、オブジェクトの一覧に戻る。
- **オブジェクトを選んだとき**: エディタを `SELECT Id FROM <オブジェクト>` に置き換える（旧版と同じ）。
- **実行したとき**: 300 ミリ秒の待ち時間に関係なく、その場で解析して FROM のオブジェクトを決め、結果の表示と CSV のファイル名に使う。
- 親リレーションの項目は `Account.Name` のようにドットでつないだ名前で、子リレーションはサブクエリで表す。
- 項目名、オブジェクト名、リレーション名は、大文字と小文字を区別せずに照らし合わせる。旧版は区別していたので、小文字で書いた SOQL では一覧が追従しなかった。
- 名前空間を省く設定がオンなら、組み立てるときに組織の名前空間を除く。照らし合わせるときは、名前空間付きと名前空間なしを同じ名前とみなす。名前空間を補うのは、カスタムの接尾辞（`__c`、`__r` など）を持つ名前だけで、ドットで区切った各部分に別々に適用する（旧版の `fullApiName` と同じ）。

プログラムからエディタを書き換えるとき（項目の追加と削除、整形、最近のクエリの読み込み、オブジェクトの選択）は、CodeMirror のトランザクションで行い、Cmd+Z（Ctrl+Z）で元に戻せるようにする。

この処理は `soql/` にまとめ、旧版の振る舞い（parity.md の各項目）をテストで押さえる。

## Tooling API と Query All

- ツールバーの Tooling API と Query All は、どちらもチェックボックス（オンとオフの切り替え）にする。
- 一方をオンにすると、もう一方はオフになり押せなくなる。Tooling API には Query All に当たる呼び出しがないからである。
- Tooling API を切り替えると、オブジェクトの一覧、describe、補完の候補を Tooling 側（`?tooling=1`）に切り替える。
- 最近のクエリを押したときは、そのクエリを実行したときの Tooling API と Query All の指定も戻す。

## 補完

補完は、旧版にあった候補（FROM のオブジェクトの項目、SOQL のキーワード）に加えて、カーソルの位置の文脈に応じた候補を出す。

### 文脈の判定

書きかけの SOQL は `soql-parser-js` では解析できないことが多い（`WHERE` で終わる文など）。
そのため、`soql/` に字句を区切る関数を置き、文字列リテラルを飛ばしながら、カーソルの位置がどの句（SELECT、FROM、WHERE、ORDER BY など）の中か、どのサブクエリの中かを判定する。
SELECT 句の時点では FROM がカーソルより後ろにあるので、文全体の字句から FROM のオブジェクトを探す。

| 位置 | 候補 |
| --- | --- |
| FROM のあと | オブジェクトの API 名とラベル |
| SELECT、WHERE、ORDER BY、GROUP BY などの句 | FROM のオブジェクトの項目 |
| `Account.` のようにドットのあと | その参照先のオブジェクトの項目（describe を取得してから出す）。ポリモーフィックな参照は最初の参照先（旧版と同じ） |
| サブクエリ `(SELECT … FROM Contacts)` の中 | 子リレーションの子オブジェクトの項目。サブクエリの FROM のあとでは、親オブジェクトの子リレーション名 |
| それ以外 | SOQL のキーワード（`SELECT`、`FROM`、`WHERE`、`ORDER BY`、`LIMIT`、日付リテラルなど） |

### CodeMirror での実現

- CodeMirror の既定の絞り込みは候補の表示名だけに効く。API 名とラベルの両方で絞り込むため、`CompletionResult` に `filter: false` を指定し、絞り込みは自前で行う。候補の `apply` には挿入する名前を入れる。
- 補完の起点を決める正規表現は、日本語のラベルでも探せるよう `\w` ではなく Unicode の文字クラス（`[\p{L}\p{N}_.]`）を使う。
- 候補の表示は「API 名 / ラベル」にする。
- 候補は、API 名が入力と前方一致するもの、ラベルが前方一致するもの、それ以外（部分一致）の順に並べる。同じ順位の中では describe の順を保つ。
- 挿入する名前は、名前空間を省く設定に従う。
- 補完は入力に合わせて開くほか、Ctrl+Space でも開く。↑↓、Enter、Esc、クリックで操作する（CodeMirror の標準）。

### 日本語入力

旧版には「変換を確定した Enter で補完を開く」振る舞いがあり、日本語のラベルで項目を探すのに使われていた。
これを引き継ぎ、変換の確定（`compositionend`）のあとに補完を開く。

ただし Safari では、変換を確定する Enter の keydown が `compositionend` の後に届くことがある。
そのまま補完を開くと、その Enter で最初の候補が確定してしまう。
そのため、`compositionend` から100ミリ秒以内の Enter と、`keyCode` が 229 の Enter は、補完の確定に使わない（補完の確定のキー割り当ての前に、これらを読み捨てるキー割り当てを置く）。
macOS の Chrome と Safari、Windows の Chrome と Edge で、日本語入力のまま手で確かめる。

## 結果の表

### 列

- 列は、SELECT 句ではなく、取得したレコードのキーを集めて作る（旧版と同じ）。親リレーションは `Account.Name` のように展開し、`attributes` は除く。子リレーション（`totalSize` と `records` を持つ値）は1つの列にし、セルには件数を出す。集計関数の `expr0` なども、キーのとおりに列にする。
- 続きのページで新しいキーが現れたら、列を足す。足した列は、同じ親リレーションの列の後ろに置く。旧版は1ページ目だけで列を決めていたので、1ページ目で親リレーションがすべて null だと、2ページ目以降のセルが `[object Object]` になっていた。
- 結果は生のレコードの配列だけを持ち、セルの値は描画のときに列の名前から求める。旧版は全セルについてオブジェクトを作っていたので、大きな結果でメモリを多く使っていた。ページを足すときは、配列を作り直さずに後ろへ足す。

### 描画

- 表は CSS grid で描き、行を TanStack Virtual で仮想化する（見えている行だけを描く）。
- 列幅は、最初のページの先頭200行の値の長さから決めて固定する。続きのページで足した列の幅は、その時点で読み込み済みの行の先頭200行から決める。仮想化した行が入れ替わるたびに列幅が揺れないようにするためである。列幅は見出しの端をドラッグして変えられないが、セルの中身は省略記号で切り、全文はセルを選ぶと見られる。
- 列が多い場合（`FIELDS(ALL)` などで数百列）も横方向は仮想化しない。描く行の数を絞っているので、数百列でも描画は間に合う。
- 列の見出しは固定し、横にスクロールしても見出しと列がずれないよう、見出しと行を同じ grid の中に置く。

### 続きのページ

- スクロールが最後の行の近く（残り50行）に来たら、続きのページを `/query/next` で取得して足す。
- 行の絞り込み中は、続きのページを自動では取得しない。絞り込むと行が少なくなり、すぐに「最後の近く」とみなされて、続きのページを次々に取得してしまうからである。代わりに、絞り込みの結果の下に「次の N 件を読み込む」ボタンを出す。1回押すと1ページ分（最大2000件）を読み込む。
- 行の絞り込みは、読み込み済みの行の、全列のセルの文字列に対する部分一致（大文字と小文字を区別しない）にする。

### 子リレーションとレコード

- 子リレーションのセルを押すと、結果の下に子レコードの表を開く。新しく実行すると閉じる。子レコードの表には、そのサブクエリの1ページ目だけを出す（サブクエリの `nextRecordsUrl` は旧版と同じく扱わない）。
- 18桁のレコード ID は、`instanceUrl/<ID>` への通常のリンクにし、新しいタブで開く（旧版と同じ）。ブラウザが Salesforce にログインしていなければ、ログイン画面になる。ヘッダーの「組織を開く」ボタンでログイン済みの状態にできる（screens.md）。

### CSV

- 続きのページをすべて取得してから作る。
- 残りの件数が1万件を超えるときは、取得を始める前に、件数と API の呼び出し回数の見込み（2000件ごとに1回）を出して確認を取る。取得中は進み具合と中止のボタンを出す。上限は設けない。
- BOM 付きで、カンマ、改行、二重引用符を含む値を二重引用符で囲む。子リレーションのセルは件数（`N rows`）を出力する。
- ファイル名は `<オブジェクト>.csv` にする。SOQL を解析できずオブジェクトがわからないときは `query.csv` にする。
- 子レコードの表を開いていても、出力するのは親の結果の表である。
- 行を絞り込んでいても、出力するのは全件である。絞り込みは表示のためだけのものとする。
- CSV のために取得したページは、結果の表には足さない。結果の表に数十万件を持たせないためである。中止したときは、取得したページを捨てる。同じページを結果の表の側でも取得することがあるが、許容する。

列の決め方、セルの値、CSV の作り方は `results/` の純粋な関数にし、テストする。

## 組織を開く

ヘッダーの組織の切り替えボタンの隣に、「組織を開く」ボタン（外部リンクのアイコン）を置く。
押すと `POST /api/orgs/:user/open` で、サーバーが `sf org open` を実行し、ログイン済みの状態で組織のホームを開く。この API はボディを受け取らず、常に組織のホームを開く。
一度開けばブラウザが Salesforce にログインした状態になるので、以後はレコードの通常のリンクで開ける。
`sf org open` は数秒かかるので、押したあとは完了まで読み込み中の表示にする。
SSH の先や WSL では、サーバーのある環境のブラウザで開くので、手元のブラウザでは開かない。

## 組織の一覧と本番の判定

- 組織の一覧のポップオーバーを開くたびに、`/api/orgs?refresh=1` で取り直す。`sf org login web` で足したり、ログインし直したりした組織を反映するためである。取り直している間は、手元にある一覧を表示しておく。
- 本番の判定は `orgs/` の純粋な関数にする。一覧では `sf org list` の情報（`kind` と `edition`）で判定し、組織を選んだあとは summary（`OrganizationType` と `IsSandbox`）で判定し直す。
- 一覧の `kind` が `scratch` の組織は、summary の結果にかかわらず本番にしない。Enterprise Edition で作ったスクラッチ組織は、`OrganizationType` が Enterprise Edition、`IsSandbox` が false になり、summary だけでは本番と区別できないからである。

## サーバーに足すもの

区切り2で、サーバーに次を足す。

- 設定の「Salesforce の応答を待つ時間」（`Settings.requestTimeoutSeconds`、既定は120、10から600までの整数）。範囲外の値は 400 で拒む。`fetch` と `sf api request rest` のタイムアウトに使い、変更は次の要求から効く。`sf` のほかのコマンド（`org list`、`show-access-token`）のタイムアウトは変えない。Salesforce の処理時間ではなく、手元の sf CLI の起動時間に依存するからである。
- describe の応答（オブジェクトの一覧と各オブジェクト）の JSON の最上位に、サーバーが取得した時刻 `fetchedAt`（ISO 8601）を足す。項目の一覧に「読み込んだ時刻」を出すためである。型は `WithFetchedAt<T>`（`src/shared/api.ts`）である。
- `POST /api/orgs/:user/open` を、ボディを受け取らず常に組織のホームを開くように変える。

sfbench のバージョンは、ビルド時に Vite の `define` で画面に埋め込み、設定画面に出す。

## 表示言語

`i18n/` に英語と日本語の文言を置き、`navigator.language` が `ja` で始まれば日本語にする。
画面上で切り替える手段は作らない（旧版と同じ）。

## テスト

- `soql/`、`results/`、`orgs/` の純粋な関数を、旧版の振る舞いを中心に単体テストする。
- 画面の部品は、主要な流れ（起動、組織の選択、オブジェクトの選択と項目の追加、実行、エラーの表示）だけを Testing Library でテストする。API はテストの中で差し替える。
- jsdom はレイアウトを計算しないので、TanStack Virtual は行を描かない。結果の表のテストでは、要素の大きさを差し替えるか、仮想化を止める設定を部品に用意する。
- CodeMirror は jsdom の上では Testing Library の入力操作で書き換えられないので、テストではエディタの `view.dispatch` で入力する。
- 実際の組織につないだ確認と、日本語入力の確認は、手で行う（`npm run dev:server` と `npm run dev:web`）。
